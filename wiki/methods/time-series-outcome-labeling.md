# 時間序列資料的結果標記（Time-series Outcome Labeling）

## 白話解釋
病人住院很多天，每天都有資料。要訓練「提早預警」模型，就得決定**每一天要標成「會發病」還是「不會發病」**。標法會直接影響模型學到什麼。

## ⭐ Kausch et al. (2024) 的標法（[[kausch2024apnea]] PDF p.4–5）
```
日期（相對確診日）： ... -5  -4  -3  -2  -1   0  +1 ... +10  +11 ...
標記：               ...  0   0   0   1   1   1  [排除 10 天] 0  ...
```
| 步驟 | 做法 | 為什麼 |
|---|---|---|
| 1. 分析單位 | 每位病人每天一列 | 每天更新一次風險 |
| 2. 陽性窗 | 確診當天 + 前 2 天 = 1 | 預測「未來 3 天內」會不會確診 |
| 3. 排除窗 | 確診後 10 天不納入 | 避開治療與恢復期 |
| 4. 其他日子 | = 0 | 無敗血症 |
| 5. 重複事件 | 同一人兩次事件需間隔 ≥10 天 | 避免同一次感染算兩次 |
| 6. 重複測量 | Huber-White 校正標準誤 | 同一人每天的資料彼此相關 |

## 設計時要想的問題（⚠️ 推論，通用原則）
1. **預測窗多長？** 太短 → 來不及處置；太長 → 訊號太弱。Kausch 選 3 天。
2. **事件後怎麼處理？** 治療會改變生理訊號，若不排除，模型可能學到「治療的樣子」而不是「生病前的樣子」。
3. **資料不平衡**：每天的事件率很低（Kausch：0.36–1.88%），AUC 可能看起來不錯，但 PPV 很低（見 [[sensitivity-specificity-ppv-npv]]）。
4. **不要用未來資料**：每一天的特徵只能用「當天以前」的資料，否則會「偷看答案」（資料洩漏）。
5. **交叉驗證要以「病人」為單位切分**：同一個人的不同天如果分散在訓練集和測試集，會高估表現。⚠️ 原文未說明是以病人或以天切分。

## 可以套用的情境（⚠️ 推論）
- 穿戴裝置／連續血糖監測預測低血糖、急診或病房的惡化預警、慢性病追蹤資料預測住院。
